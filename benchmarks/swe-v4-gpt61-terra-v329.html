October 30, 2026 · Morgan Linton · 115 runs · Code quality protocol v3.29

GPT-6.1 Terra across every effort level

115 runs of OpenAI’s GPT-6.1 Terra (gpt-6.1-terra) through the Codex CLI on a ChatGPT subscription, 23 tasks at each of five effort levels, Low to Max, the day after the model’s release. GPT-6.1 Terra is a new model, the second Terra on the board after GPT-5.6 Terra. Code quality carries 33% of the combined score and is judged for a human reader by Muse Spark 1.3 and Grok 4.6, the panel that judged Claude Opus 5.5, GPT-6.1 Sol and GPT-6 Astra, so GPT-6.1 Terra takes its place on the Frontier v4 leaderboard beside them. Every run finished inside the 3-hour task bound, and every cell is judged on all 23 runs, one of them through an escape-spelling recovery described under the results table.

How the test works

  1. 1

    A retired program to rebuild

    Each of the 23 tasks is a legacy binary with a written specification and an issue. Its real behaviour departs from the specification in documented ways, and hidden tests check the rewrite against the binary.

  2. 2

    One attempt per task and level

    GPT-6.1 Terra works in Codex with the binary, the specification and the code, once per task at each effort level, inside a flat 3-hour bound, one task at a time.

  3. 3

    Tests and two judges score it

    Hidden tests give functional correctness. Two calibrated judges from labs other than OpenAI rate the code for a human reader and try to recover the documented departures.

  4. 4

    Scores, time and cost per level

    Each level gets a combined score, tasks passed, minutes and API-equivalent cost at OpenAI’s list price.

Combined score = 50% functional correctness + 8.5% lint and complexity + 8.5% security + 33% Code quality, averaged over the 23 runs in each level, as on every other board column. Frontier Code quality is the reviewed layer plus intent recovery; it is never compared with Routine v1 Code quality.

Across every effort level

GPT-6.1 Terra ran every task once at each of the five effort levels Codex offers for it (Extra-high is Codex’s xhigh), 23 tasks per cell, through Codex CLI 0.159.0 on a ChatGPT subscription on October 27, 2026, from 15:14 to 23:16 UTC, the day after OpenAI released it, on the owner’s Mac, one task at a time. Combined score weights are 50% functional correctness, 8.5% lint and complexity, 8.5% security and 33% Code quality, judged for a named human reader by Muse Spark 1.3 and Grok 4.6 with a ground-truth intent-recovery probe. No run reached the flat 3-hour task bound; the longest, Extra-high paddockcore, took 19.5 minutes. All 115 runs carry a published Code quality score.

Combined score

74.95 at Low to 90.00 at Max

The score climbs with effort, unevenly: 74.95 at Low, 80.10 at Medium, 79.19 at High, 83.68 at Extra-high and 90.00 at Max. The step from Extra-high to Max, 6.32 points, is the largest, and Max is the only level with a standard error under 2 points (0.39).

Tasks passed

13, 12, 15, 16 and 23 of 23

GPT-6.1 Terra fully solves 12 to 16 tasks from Low to Extra-high and every task at Max. Of the 231 hidden behaviours the tasks test for, it fixes 170, 188, 176, 205 and 231. Six tasks fail at every level from Low to Extra-high and pass only at Max.

Code quality

66.55 to 76.59

The judges rate the code 66.55 at Low, 67.29 at Medium, 69.96 at High, 70.94 at Extra-high and 76.59 at Max, rising with effort, with standard errors of 1.07 to 1.35.

Runtime and cost

2.8 to 6.9 min · $0.11 to $0.36 per task

Max takes about two and a half times as long as Low and costs about three times as much. The whole sweep took 8.0 hours of solver time and prices at $22.49 for 115 runs, $0.20 per task, at GPT-6.1 Terra’s list rates.

Max settlecore is published through a recovery. Muse Spark 1.3’s intent probe of Max settlecore quoted a byte-string line from the code with its escapes decoded into control characters, on both of its two attempts, so the quote no longer matched the code. That is the JSON-escaping slip the operator rule recover_escaped_excerpts was written for under v3.18, for Muse’s probe of GPT-6.1 Sol at High codeccore: the rule writes such characters back as the source spells them, after which the excerpt must be verbatim and the attempt must pass every other check. The rule spelled a decoded NUL byte only as \0, and this source writes \x00, so the probe was first marked invalid and the first summary published 114 of the 115 runs, with Max on 22. The owner chose on October 29 to recover it under the rule. The rule now tries both spellings (harness PR #239), the invalid marker is kept beside the recovered call, the one missing answer-key match was made on October 30, and the summary was rebuilt. Max moved from 89.95 on 22 runs to 90.00 on 23; settlecore scores 91.11, with Code quality 80.30. No other call changed.

What Code quality measures

Every judge receives the same rubric, frozen by hash before any review. It names the reader it scores for: an engineer who has never seen the code, reads it top to bottom without running it, and must make a correct change in one sitting. It tells the judge that its own ease at parsing dense code is not evidence of readability. Six dimensions are scored 0 to 4 in half steps against written anchors: naming, presentation and intent form the human readability sub-score; structure, changeability and verifiability form the maintainability sub-score. Every score must cite an exact excerpt from the code and a concrete consequence for that reader. The host computes the sub-scores; the judge does no arithmetic.

The 33 points have three designed layers. The reviewed panel carries 24 points. An intent-recovery probe carries 9: the judge, given only the specification and the code, lists where the code departs from the specification, and a separate call matches that list against a frozen answer key, over the departures the submission passed tests for. The third layer, measured maintenance, is designed for 12 points but is not yet built, so the pre-registered 24 plus 9 split is in force. Frontier Code quality is therefore the reviewed layer plus intent recovery, and it is never compared with Routine v1 Code quality, which is scored on a different suite and population.

Judges and calibration

The scored panel is Muse Spark 1.3 (Meta) through the Muse CLI on its Standard tier, and Grok 4.6 (xAI) through the Cursor CLI at medium effort, with equal weight, the same settings and pinned Muse binary as under v3.24. Grok 4.6 ran through the Cursor CLI pinned to version 2026.10.01-e373342, the build v3.23 and v3.24 used, with a digest of its version directory checked before every stage; Cursor had since updated itself to a newer build. Neither lab is OpenAI. Every session is fresh, tools are disabled, the workspace is empty, model identity is checked per call from the CLI’s own records, and solver labels are withheld. Protocol v3.29 changes nothing in the rubric, controls, quirk keys, gates, repeats, seed, weights or judges from v3.24; it applies the protocol to this population.

Before scoring a single submission, each judge reviews ten held-out programs that implement the same ledger specification: clear, compressed, compressed then auto-formatted, verbose with duplicated policy, needlessly abstracted, misleadingly commented, narrated with a comment on every line, a documented legacy quirk, an embedded instruction to give full marks, and hidden module state. Each program is reviewed five times in a seeded order. Twenty gates fixed in advance check that the judge sees the construct; a judge may miss at most one gate by at most half a point. Both judges retook the exam under v3.29 before any counted call.

How it was run

  • The model. GPT-6.1 Terra through the Codex CLI as gpt-6.1-terra, released by OpenAI on October 26, 2026. Codex does not report the serving model, so model identity is the model requested.
  • Codex CLI 0.159.0. Pinned by version from its own install, the version GPT-6.1 Sol ran on, signed in with a ChatGPT subscription, in codex exec with Codex’s workspace-write sandbox, network access off, user configuration ignored and no saved session.
  • Five levels. Codex takes low, medium, high, xhigh and max for GPT-6.1 Terra; the board’s Extra-high is xhigh.
  • A model metadata notice. In three Extra-high runs (hedgecore, pacecore and tallycore, run back to back), Codex printed its notice that it had no model metadata for gpt-6.1-terra and used fallback metadata. All three passed every hidden test, and they stay in the population; no other run printed it.
  • From a tagged run worktree. Every run ran from bench/2026-10-27-gpt61-terra-frontier-v4, so every run summary carries a clean source block and records the frozen suite lock’s task hash.
  • No timeouts, no retries. Every run finished inside the flat 3-hour bound; the longest, Extra-high paddockcore, took 19.5 minutes. The sweep log shows each level complete on its first attempt.
  • Where and how. The owner’s Mac, one task at a time, on October 27, 2026, from 15:14 to 23:16 UTC. Every integrity audit is clean: no web access, and no benchmark data or answer-key paths.
  • The day after release. The Codex CLI is pinned by version, but the sweep cannot pin what OpenAI serves under the model id.
  • One attempt per task and level. Runs were not repeated, and effort labels are Codex’s own.

Evidence and reproduction

Public files contain all 115 run measurements, both judges’ six-dimension sub-scores and intent-recovery scores per run, the combined score from each judge alone, hidden behaviours fixed, integrity-audit verdicts, each run’s task hash and Codex notices, raw tokens and API-equivalent cost estimates per run, five aggregates, every calibration gate value, the exact judge protocol text, the operator record for the Max settlecore recovery and source hashes. Each run’s Code quality is (0.24 × reviewed score + 0.09 × intent recovery) / 0.33, where both terms are the equal mean of the two judges, or the reviewed score alone when the run passed no quirk family. The combined score is 100 × (0.50F + 0.085Q + 0.085S + 0.33C / 100). The reproduction guide gives the public arithmetic checks and links the protocol document, the operations log, the decision record, the Codex adapter and the code in the harness repository.

No human rated anything; the scores are model judgment for a human reader, not human validation. Hash checks bind the export to frozen files, including the operator’s superseded marker and the recovered probe; they do not prove that judges were unbiased or that no training overlap exists.

Withheld: raw prompts and responses, submitted patches and reconstructed sources, the quirk answer keys (they describe hidden-test behaviour), reviewer session identifiers and usage receipts, solver event streams (a structure-only redacted trace of every run, every agent message, command and file change with its timing, is public in vulcanbench-gpt61-terra-traces), and host binary paths. Summed solver time is 8.02 hours; judging is excluded.
