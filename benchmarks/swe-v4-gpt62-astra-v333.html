November 24, 2026 · Morgan Linton · 115 runs · Code quality protocol v3.33

GPT-6.2 Astra across every effort level

115 runs of OpenAI’s GPT-6.2 Astra (gpt-6.2-astra) through the Codex CLI on a ChatGPT subscription, 23 tasks at each of five effort levels, Low to Max. GPT-6.2 Astra is the second Astra on the board, after GPT-6 Astra, and ran on the same Codex CLI build as GPT-6.2 Sol, so the two GPT-6.2 columns differ only in the model. Code quality carries 33% of the combined score and is judged for a human reader by Muse Spark 1.3 and Grok 4.6, the panel that judged GPT-6 Astra, GPT-6.2 Sol and Gemini 4 Neon, so GPT-6.2 Astra takes its place on the Frontier v4 leaderboard beside them. Every run passed every hidden test and finished inside the 3-hour task bound, and every run is scored by both judges.

How the test works

  1. 1

    A retired program to rebuild

    Each of the 23 tasks is a legacy binary with a written specification and an issue. Its real behaviour departs from the specification in documented ways, and hidden tests check the rewrite against the binary.

  2. 2

    One attempt per task and level

    GPT-6.2 Astra works in Codex with the binary, the specification and the code, once per task at each effort level, inside a flat 3-hour bound, one task at a time.

  3. 3

    Tests and two judges score it

    Hidden tests give functional correctness. Two calibrated judges from labs other than OpenAI rate the code for a human reader and try to recover the documented departures.

  4. 4

    Scores, time and cost per level

    Each level gets a combined score, tasks passed, minutes and API-equivalent cost at OpenAI’s list price.

Combined score = 50% functional correctness + 8.5% lint and complexity + 8.5% security + 33% Code quality, averaged over the 23 runs in each level, as on every other board column. Frontier Code quality is the reviewed layer plus intent recovery; it is never compared with Routine v1 Code quality.

Across every effort level

GPT-6.2 Astra ran every task once at each of the five effort levels Codex offers for it (Extra-high is Codex’s xhigh), 23 tasks per cell, through Codex CLI 0.166.0 on a ChatGPT subscription from November 23, 2026, 02:08 UTC, to 12:38 UTC the same day (the evening of November 22 to the early morning of November 23 in Pacific time), on the owner’s Mac, one task at a time. Combined score weights are 50% functional correctness, 8.5% lint and complexity, 8.5% security and 33% Code quality, judged for a named human reader by Muse Spark 1.3 and Grok 4.6 with a ground-truth intent-recovery probe. No run reached the flat 3-hour task bound; the longest, Max quotacore, took 18.4 minutes. All 115 runs carry a published Code quality score from both judges.

Combined score

87.68 at Low to 89.42 at Max

The score climbs from 87.68 at Low to 88.89 at Medium and 89.26 at High, dips to 89.05 at Extra-high and ends at 89.42 at Max. From Medium up the four levels sit within 0.53 points, about one and a half standard errors, so most of what effort buys arrives by Medium.

Tasks passed

23 of 23 at every level

GPT-6.2 Astra fully solves every task at every level and fixes all 231 hidden behaviours the tasks test for, in all 115 runs. With functional correctness at 100 everywhere, the differences between levels come from Code quality, lint and security.

Code quality

67.27 to 74.53

Code quality rises with effort: 67.27 at Low, 70.65 at Medium, 72.88 at High, 72.98 at Extra-high and 74.53 at Max, with standard errors of 0.96 to 1.15. The security scan moves the other way, from 99.13 at Low to 90.87 at Max, as more runs carry a low-severity finding, which is why the combined score rises less than Code quality does.

What Code quality measures

Every judge receives the same rubric, frozen by hash before any review. It names the reader it scores for: an engineer who has never seen the code, reads it top to bottom without running it, and must make a correct change in one sitting. It tells the judge that its own ease at parsing dense code is not evidence of readability. Six dimensions are scored 0 to 4 in half steps against written anchors: naming, presentation and intent form the human readability sub-score; structure, changeability and verifiability form the maintainability sub-score. Every score must cite an exact excerpt from the code and a concrete consequence for that reader. The host computes the sub-scores; the judge does no arithmetic.

The 33 points have three designed layers. The reviewed panel carries 24 points. An intent-recovery probe carries 9: the judge, given only the specification and the code, lists where the code departs from the specification, and a separate call matches that list against a frozen answer key, over the departures the submission passed tests for. The third layer, measured maintenance, is designed for 12 points but is not yet built, so the pre-registered 24 plus 9 split is in force. Frontier Code quality is therefore the reviewed layer plus intent recovery, and it is never compared with Routine v1 Code quality, which is scored on a different suite and population.

Judges and calibration

The scored panel is Muse Spark 1.3 (Meta) through the Muse CLI on its Standard tier, and Grok 4.6 (xAI) through the Cursor CLI at medium effort, with equal weight, the same settings and pinned Muse binary as under v3.24. Grok 4.6 ran through the Cursor CLI pinned to version 2026.10.01-e373342, the build every Grok 4.6 round since v3.23 used, with a digest of its version directory checked before every stage; Cursor had since updated itself to a newer build, which was not used. Neither lab is OpenAI. Every session is fresh, tools are disabled, the workspace is empty, model identity is checked per call from the CLI’s own records, and solver labels are withheld. Protocol v3.33 changes nothing in the rubric, controls, quirk keys, gates, repeats, seed, weights or judges from v3.24; it applies the protocol to this population. The owner chose this panel on November 23.

Before scoring a single submission, each judge reviews ten held-out programs that implement the same ledger specification: clear, compressed, compressed then auto-formatted, verbose with duplicated policy, needlessly abstracted, misleadingly commented, narrated with a comment on every line, a documented legacy quirk, an embedded instruction to give full marks, and hidden module state. Each program is reviewed five times in a seeded order. Twenty gates fixed in advance check that the judge sees the construct; a judge may miss at most one gate by at most half a point. Both judges retook the exam under v3.33 before any counted call; had either failed, the other would have published alone.

How it was run

  • The model. GPT-6.2 Astra through the Codex CLI as gpt-6.2-astra. Codex does not report the serving model, so model identity is the model requested.
  • Codex CLI 0.166.0. Pinned by version from the install the GPT-6.2 Sol column used, signed in with a ChatGPT subscription, in codex exec with Codex’s workspace-write sandbox, network access off, user configuration ignored and no saved session.
  • The plan. The ChatGPT login reported plan prolite, the plan GPT-6.2 Sol ran on; earlier GPT columns ran on ChatGPT Pro. The plan sets usage limits, not the model served, and no run waited on a usage limit.
  • Five levels. Codex takes low, medium, high, xhigh and max for GPT-6.2 Astra; the board’s Extra-high is xhigh.
  • From a tagged run worktree. Every run ran from bench/2026-11-22-gpt62-astra-frontier-v4, so every run summary carries a clean source block and records the frozen suite lock’s task hash.
  • No timeouts, no retries, no notices. Every run finished inside the flat 3-hour bound; the longest, Max quotacore, took 18.4 minutes. The sweep log shows each level complete on its first attempt, and no run printed a Codex warning.
  • Where and how. The owner’s Mac, one task at a time, on November 23, 2026, from 02:08 to 12:38 UTC. Every integrity audit is clean: no web access, and no benchmark data or answer-key paths.
  • What is pinned. The Codex CLI is pinned by version, but the sweep cannot pin what OpenAI serves under the model id.
  • One attempt per task and level. Runs were not repeated, and effort labels are Codex’s own.

Evidence and reproduction

Public files contain all 115 run measurements, both judges’ six-dimension sub-scores and intent-recovery scores per run, the combined score from each judge alone, hidden behaviours fixed, integrity-audit verdicts, each run’s task hash, raw tokens and API-equivalent cost estimates per run, five aggregates, every calibration gate value, the exact judge protocol text, the call record with each retry’s cause, and source hashes. Each run’s Code quality is (0.24 × reviewed score + 0.09 × intent recovery) / 0.33, where both terms are the equal mean of the two judges. The combined score is 100 × (0.50F + 0.085Q + 0.085S + 0.33C / 100). The reproduction guide gives the public arithmetic checks and links the protocol document, the operations log, the decision record, the Codex adapter and the code in the harness repository.

No human rated anything; the scores are model judgment for a human reader, not human validation. Hash checks bind the export to frozen files; they do not prove that judges were unbiased or that no training overlap exists.

Withheld: raw prompts and responses, submitted patches and reconstructed sources, the quirk answer keys (they describe hidden-test behaviour), reviewer session identifiers and usage receipts, solver event streams, and host binary paths. Summed solver time is 10.50 hours; judging is excluded.
