Cost assumptions and evaluation scope

Astra’s central estimate assumes requests of at most 272,000 input tokens. Per-request sizes were not logged. Its full-sweep estimate is $225.04, with a conservative long-context upper bound of $419.42, versus $1,159.10 for Fable with fallbacks. Astra remains cheaper at each matched effort under that bound. These are estimates from exposed CLI receipts, not reconstructed API invoices.

Price sources: OpenAI Astra pricing and Anthropic pricing. The costs CSV includes per-effort totals and Astra’s long-context sensitivity bound.

Each run repairs a Python replacement for a C-built binary. There is one attempt per task and effort, with a 10-hour per-task limit. Effort labels are harness-specific, not equal compute budgets. Reviewer tools were disabled and solver identity labels were omitted. Review did not change the original submissions or functional grades.

Code quality is the 20% model-based review factor in the methodology. Automated quality is a separate 15% factor. All comparisons on this card use the same 50/15/15/20 weights and equal-panel review protocol.

What Code quality measures

Each solution receives three Astra and three Claude reviews at medium effort, using correctness, readability and maintainability personas. Each panel's mean is rounded to four decimal places on a 0 to 1 scale; the two panels receive equal weight. The original issue, complete saved patch and verifier outcome are provided; solver labels are omitted and tools are disabled.

The actual rubric asks how human-like and high-quality the solution is on a 0 to 100 scale. It has no anchored score bands. These are model judgments, not human validation, authorship detection or an objective production-readiness scale. Different reviewer calibration can change close rankings.

Exact general prompts and personas · Proposed future calibration protocol. The proposal was not used for these scores.

Evidence and reproduction

Public files contain all 230 run measurements, 1,380 selected ratings and 1,386 reviewer-call dispositions. Verification recomputes the fixed score formula and prices exposed token receipts against the frozen rate snapshot. The reproduction guide links pinned task, harness and grader sources and distinguishes public arithmetic checks from a new model run.

All 23 task definitions match recorded task hashes. Original harness commit identities were not logged; the linked harness commit is a reference snapshot, not a verified execution lockfile. Raw trajectories, patches and task-specific reviewer evidence for these runs are not published. Hash checks do not prove no cheating, prohibited access or training-data overlap.

Summed solver time was 70.75 hours: 12.00 for Astra and 58.75 for Fable. First-start to last-finish spans were 12.01 and 80.32 hours respectively; gaps and overlap mean those spans must not be added. Judging is excluded.

For a stronger follow-up, freeze and calibrate an anchored rubric before evaluation, repeat paired runs with fixed CLI versions, counterbalance execution order, and record request-level model identity, usage and host load. Do not treat extra score separation as a calibration goal.
