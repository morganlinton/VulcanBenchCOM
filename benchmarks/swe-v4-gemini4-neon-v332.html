November 21, 2026 · Morgan Linton · 92 runs · Code quality protocol v3.32

Gemini 4 Neon across every effort level

92 runs of Google’s Gemini 4 Neon (gemini-4-neon) through the Antigravity CLI on a Google AI Pro subscription, 23 tasks at each of the four effort levels Antigravity offers for it, Low to Extra-high. Gemini 4 Neon is the first Google model on the board. Code quality carries 33% of the combined score and is judged for a human reader by Muse Spark 1.3 and Grok 4.6, the panel that judged Claude Opus 5.5, GPT-6.1 Sol and GPT-6.2 Sol, so Gemini 4 Neon takes its place on the Frontier v4 leaderboard beside them. Every run finished inside the 3-hour task bound. Low and Extra-high are judged on 22 of 23 runs, for the reason given under the results table.

How the test works

  1. 1

    A retired program to rebuild

    Each of the 23 tasks is a legacy binary with a written specification and an issue. Its real behaviour departs from the specification in documented ways, and hidden tests check the rewrite against the binary.

  2. 2

    One attempt per task and level

    Gemini 4 Neon works in Antigravity with the binary, the specification and the code, once per task at each effort level, inside a flat 3-hour bound, one task at a time.

  3. 3

    Tests and two judges score it

    Hidden tests give functional correctness. Two calibrated judges from labs other than Google rate the code for a human reader and try to recover the documented departures.

  4. 4

    Scores, time and cost per level

    Each level gets a combined score, tasks passed, minutes and API-equivalent cost at Google’s list price.

Combined score = 50% functional correctness + 8.5% lint and complexity + 8.5% security + 33% Code quality, averaged over the judged runs in each level, as on every other board column. Frontier Code quality is the reviewed layer plus intent recovery; it is never compared with Routine v1 Code quality.

Across every effort level

Gemini 4 Neon ran every task once at each of the four effort levels Antigravity offers for it (Extra-high is Antigravity’s xhigh; there is no Max), 23 tasks per cell, through Antigravity CLI 1.5.12 on a Google AI Pro subscription from November 20, 2026, 13:50 UTC, to November 21, 09:58 UTC, on the owner’s Mac, one task at a time. About nine of those hours were waits on the plan’s usage quota. Combined score weights are 50% functional correctness, 8.5% lint and complexity, 8.5% security and 33% Code quality, judged for a named human reader by Muse Spark 1.3 and Grok 4.6 with a ground-truth intent-recovery probe. No run reached the flat 3-hour task bound; the longest, Medium granarycore, took 19.0 minutes.

Combined score

84.32 at Low to 87.87 at High

Low is the outlier: 84.32, then 87.48 at Medium, 87.87 at High and 87.70 at Extra-high. Above Low the three levels sit within 0.4 points of each other, less than one standard error.

Tasks passed

17 of 23 at Low, 23 of 23 above

At Low, six tasks pass only part of their hidden tests (220 of the 231 hidden behaviours fixed). From Medium up Gemini 4 Neon fully solves every task and fixes all 231, so the differences between those levels come from Code quality, lint and security.

Code quality

66.15 to 69.07

The judges rate the code 66.15 at Low, 67.87 at Medium, 69.07 at High and 68.69 at Extra-high, with standard errors of 1.21 to 1.45: a slow rise of about three points, flat from High.

Runtime and cost

5.1 to 10.1 min · $0.73 to $1.80 per task

Extra-high takes twice as long as Low and costs two and a half times as much, for no score over High. The whole sweep took 10.6 hours of solver time and prices at $106.84 for 92 runs, $1.16 per task, at Gemini 4 Neon’s list rates.

What Code quality measures

Every judge receives the same rubric, frozen by hash before any review. It names the reader it scores for: an engineer who has never seen the code, reads it top to bottom without running it, and must make a correct change in one sitting. It tells the judge that its own ease at parsing dense code is not evidence of readability. Six dimensions are scored 0 to 4 in half steps against written anchors: naming, presentation and intent form the human readability sub-score; structure, changeability and verifiability form the maintainability sub-score. Every score must cite an exact excerpt from the code and a concrete consequence for that reader. The host computes the sub-scores; the judge does no arithmetic.

The 33 points have three designed layers. The reviewed panel carries 24 points. An intent-recovery probe carries 9: the judge, given only the specification and the code, lists where the code departs from the specification, and a separate call matches that list against a frozen answer key, over the departures the submission passed tests for. The third layer, measured maintenance, is designed for 12 points but is not yet built, so the pre-registered 24 plus 9 split is in force. Frontier Code quality is therefore the reviewed layer plus intent recovery, and it is never compared with Routine v1 Code quality, which is scored on a different suite and population.

Judges and calibration

The scored panel is Muse Spark 1.3 (Meta) through the Muse CLI on its Standard tier, and Grok 4.6 (xAI) through the Cursor CLI at medium effort, with equal weight, the same settings and pinned Muse binary as under v3.24. Grok 4.6 ran through the Cursor CLI pinned to version 2026.10.01-e373342, the build v3.23 to v3.31 used, with a digest of its version directory checked before every stage. Neither lab is Google. Every session is fresh, tools are disabled, the workspace is empty, model identity is checked per call from the CLI’s own records, and solver labels are withheld. Protocol v3.32 changes nothing in the rubric, controls, quirk keys, gates, repeats, seed, weights or judges from v3.24; it applies the protocol to this population. The owner chose this panel on November 21.

Before scoring a single submission, each judge reviews ten held-out programs that implement the same ledger specification: clear, compressed, compressed then auto-formatted, verbose with duplicated policy, needlessly abstracted, misleadingly commented, narrated with a comment on every line, a documented legacy quirk, an embedded instruction to give full marks, and hidden module state. Each program is reviewed five times in a seeded order. Twenty gates fixed in advance check that the judge sees the construct; a judge may miss at most one gate by at most half a point. Both judges retook the exam under v3.32 before any counted call.

How it was run

  • The model. Gemini 4 Neon through the Antigravity CLI, which takes the effort level as part of the model name (gemini-4-neon-low to gemini-4-neon-xhigh). Antigravity reports the model it served, gemini-4-neon, on every run.
  • Antigravity CLI 1.5.12. Pinned by file hash, signed in with the owner’s Google AI Pro subscription, in headless mode with a private home folder per run inside the harness’s macOS sandbox. Antigravity offers no Max level for Neon, so the sweep has four levels.
  • A custom agent with no web tools. Antigravity’s default agent carries a web search tool that its permission settings cannot switch off. Every run instead used a custom main agent limited to the default file and shell tools (read file, write file, edit file and run command), whose prompt body is Antigravity’s own identity text, verbatim; URL, browser and MCP tools were also denied. Every archived tool call is one of those four tools, and every integrity audit is clean: no web search or fetch, and no benchmark data or answer-key paths.
  • The plan’s usage quota. The AI Pro plan refused 40 attempts on its usage quota (10 at Medium, 8 at High, 22 at Extra-high), four of them at Extra-high cut off mid-task. Each was classified as infrastructure and rerun from scratch after the quota reset, so the sweep waited about nine hours in all; no refused attempt is in the population or the cost.
  • From a tagged run worktree. Every run ran from bench/2026-11-20-gemini4-neon-frontier-v4, so every run summary carries a clean source block and records the frozen suite lock’s task hash. A first launch the evening before was stopped after one Low run: shell heredocs failed inside the sandbox, a fault no earlier harness had met. The fix went in through its own pull request, the voided run was set aside, and the sweep restarted from Low on the new tag.
  • The pinned binary. During setup, before any run, Antigravity updated itself to 1.6.1 in place; the pinned 1.5.12 binary was restored by hash and its folder made read-only, which the updater skips, and the launcher checks the hash before every run. The run receipts written from the sweep tag still describe the update control as an environment variable, which turned out not to stop the updater.
  • No timeouts. Every run finished inside the flat 3-hour bound; the longest, Medium granarycore, took 19.0 minutes.
  • Where and how. The owner’s Mac, one task at a time, from November 20, 2026, 13:50 UTC, to November 21, 09:58 UTC.
  • One attempt per task and level. Runs were not repeated, and effort labels are Antigravity’s own.

Evidence and reproduction

Public files contain all 92 run measurements, both judges’ six-dimension sub-scores and intent-recovery scores for the 90 published runs, the combined score from each judge alone, hidden behaviours fixed, integrity-audit verdicts, tool-call counts, each run’s task hash, raw tokens and API-equivalent cost estimates per run, four aggregates, every calibration gate value, the exact judge protocol text, the operator records for the two unpublished rows, and source hashes. Each run’s Code quality is (0.24 × reviewed score + 0.09 × intent recovery) / 0.33, where both terms are the equal mean of the two judges. The combined score is 100 × (0.50F + 0.085Q + 0.085S + 0.33C / 100). The reproduction guide gives the public arithmetic checks and links the protocol document, the operations log, the decision record, the Antigravity adapter and the code in the harness repository.

No human rated anything; the scores are model judgment for a human reader, not human validation. Hash checks bind the export to frozen files, including the operator’s two invalidation markers; they do not prove that judges were unbiased or that no training overlap exists.

Withheld: raw prompts and responses, the model’s thinking text, submitted patches and reconstructed sources, the quirk answer keys (they describe hidden-test behaviour), reviewer session identifiers and usage receipts, solver event streams and tool-call inputs, and host binary paths. Summed solver time is 10.56 hours; judging is excluded.
