All VulcanBench Frontier v4 reports

October 12, 2026 · 115 runs · Code quality protocol v3.24

Claude Haiku 5.5 across every effort level

115 runs of Claude Haiku 5.5 through Claude Code on a Claude Max subscription, 23 tasks at each of five effort levels, Low to Max. Code quality carries 33% of the combined score and is judged for a human reader by Muse Spark 1.3 and Grok 4.6 under the same rubric, controls and gates as the other Frontier v4 reports, so Haiku 5.5 takes its place on the Frontier v4 leaderboard beside Claude Sonnet 5.5 and Claude Opus 5.5. Every run finished inside the 3-hour task bound. Four runs carry no Code quality score: three that a safety classifier stopped with an empty patch, and one whose judge probe had no valid answer; all four count in tasks passed, time and cost. For Haiku 5.5 beside Claude Sonnet 5.5, GPT-6.1 Sol and GPT-6 Luna, see the comparison page.

How the test works

  1. 1

    A retired program to rebuild

    Each of the 23 tasks is a legacy binary with a written specification and an issue. Its real behaviour departs from the specification in documented ways, and hidden tests check the rewrite against the binary.

  2. 2

    One attempt per task and level

    Claude Haiku 5.5 works in Claude Code with the binary, the specification and the code, once per task at each effort level, inside a flat 3-hour bound, one task at a time.

  3. 3

    Tests and two judges score it

    Hidden tests give functional correctness. Two calibrated judges from labs other than Anthropic rate the code for a human reader and try to recover the documented departures.

  4. 4

    Scores, time and cost per level

    Each level gets a combined score, tasks passed, minutes and cost. Cost is Claude Code’s own list-price total for each run, beside a floor and a ceiling for Haiku’s two price tiers.

Combined score = 50% functional correctness + 8.5% lint and complexity + 8.5% security + 33% Code quality, averaged over the judged runs in each level, as on every other board column. Frontier Code quality is the reviewed layer plus intent recovery; it is never compared with Routine v1 Code quality.

Across every effort level

Claude Haiku 5.5 (claude-haiku-5-5) ran every task once at each of its five effort levels, 23 tasks per cell, through Claude Code 2.1.293 to 2.1.296 on a Claude Max subscription, from October 8, 10:40 UTC, to October 11, 22:49 UTC, 2026, on the owner’s Mac in the local sandbox, one task at a time, with two pauses between tasks. Combined score weights are 50% functional correctness, 8.5% lint and complexity, 8.5% security and 33% Code quality, judged for a named human reader by Muse Spark 1.3 and Grok 4.6 with a ground-truth intent-recovery probe. No run reached the flat 3-hour task bound; the longest, Medium depotcore, took 126 minutes. Anthropic’s default effort for Haiku 5.5 is Medium, on the API and in Claude Code.

Combined score

84.03 to 92.16

Combined score is 84.42 at Low and 84.03 at Medium, then rises to 88.01 at High, 91.83 at Extra-high and 92.16 at Max. Standard errors narrow from 1.97 and 2.50 at Low and Medium to 0.39 and 0.37 at the top two levels.

Tasks passed

13 of 23 at Low and Medium, 22 of 23 from Extra-high

pass@1 is 0.565 (±0.106) at Low and Medium, 0.739 (±0.094) at High and 0.957 (±0.043) at Extra-high and Max. Of the 231 hidden behaviours the tasks test for, it fixes 202, 195, 215, 216 and 216. The one task missed at Extra-high and Max is paddockcore, stopped by a safety classifier.

Code quality

74.83 to 81.30

Code quality rises at every step, from 74.83 at Low to 81.30 at Max, with standard errors of 1.03 to 1.58.

Runtime and cost

19.0 to 27.7 min · $0.84 to $1.54 per task

Extra-high is the fastest and cheapest level (19.0 minutes, $0.84 a task); Max is the slowest and dearest (27.7 minutes, $1.54). The whole sweep comes to $138.31 as Claude Code reports it, between a floor of $31.10 and a ceiling of $155.50.

Four runs without a Code quality score

  • Three safety-classifier stops. On paddockcore at Medium, Extra-high and Max, a safety classifier stopped the session while Haiku 5.5 probed the legacy binary, after 4.7, 9.3 and 29.7 minutes, and the run ended with an empty patch: there is no code to review. As for Claude Opus 5.5’s High depotcore, these runs are excluded from judging, count as failed tasks, and are priced and timed. The combined score at those three levels is over the judged runs, so it does not include these failures; tasks passed does.
  • Max codeccore is unpublished. Grok 4.6’s intent probe for this run gave no valid answer after the protocol’s single retry: attempt 1 quoted a code line absent from the run, which no recovery rule accepts, and attempt 2 was not valid JSON. The frozen protocol therefore publishes no Code quality or combined score for the run, exactly as for the same task under v3.7 and v3.17. The run passed its tests, so it counts as a passed task, and it is priced and timed.

Max is therefore judged on 21 of 23 runs, and Medium and Extra-high on 22.

Cost, tokens and Haiku’s price tiers

Haiku 5.5 has two list prices per token. Anthropic’s pricing page, checked October 7, 2026, charges $0.10 input, $0.125 for 5-minute cache writes, $0.01 for cache reads and $0.50 output per million tokens for prompts up to 100,000 tokens, and five times as much on every line ($0.50, $0.625, $0.05 and $2.50) for prompts over 100,000 tokens. Claude Code’s receipts hold the session’s cumulative usage, not the size of each request, so a run cannot be split between the tiers after the fact. Each run therefore carries three figures: Claude Code’s own list-price total (cli_reported_cost_usd, which prices each request at its own tier and is the published cost), a floor that prices every request at the standard tier, and a ceiling that prices every request at the higher one. Haiku 5.5 ran on a Claude Max subscription, so all three are API-equivalent estimates, not bills; judging is excluded.

What Code quality measures

Every judge receives the same rubric, frozen by hash before any review. It names the reader it scores for: an engineer who has never seen the code, reads it top to bottom without running it, and must make a correct change in one sitting. It tells the judge that its own ease at parsing dense code is not evidence of readability. Six dimensions are scored 0 to 4 in half steps against written anchors: naming, presentation and intent form the human readability sub-score; structure, changeability and verifiability form the maintainability sub-score. Every score must cite an exact excerpt from the code and a concrete consequence for that reader. The host computes the sub-scores; the judge does no arithmetic.

The 33 points have three designed layers. The reviewed panel carries 24 points. An intent-recovery probe carries 9: the judge, given only the specification and the code, lists where the code departs from the specification, and a separate call matches that list against a frozen answer key, over the departures the submission passed tests for. The third layer, measured maintenance, is designed for 12 points but is not yet built, so the pre-registered 24 plus 9 split is in force. Frontier Code quality is therefore the reviewed layer plus intent recovery, and it is never compared with Routine v1 Code quality, which is scored on a different suite and population.

Judges and calibration

The scored panel is Muse Spark 1.3 (Meta) through the Muse CLI on its Standard tier, and Grok 4.6 (xAI) through the Cursor CLI at medium effort, with equal weight. Both judges are from labs other than Anthropic, so neither grades a relative of Haiku 5.5. Every session is fresh, tools are disabled, the workspace is empty, model identity is checked per call from the CLI’s own records, and solver labels are withheld. Protocol v3.24 changes nothing in the rubric, controls, quirk keys, gates, repeats, seed, weights or judge settings from v3.23; it applies the protocol to this population, and both judges retook the calibration exam under it before any counted call.

Judge settings and versions. The judge settings are read from the original v3.3 and v3.4 protocol files, recovered from the owner’s private backup, whose sha256 equal the published values (v3.3 b82da598, v3.4 1d80e097). Muse Spark 1.3 ran the same binary as every earlier round (sha256 match). Grok 4.6 ran through Cursor CLI 2026.10.01-e373342, pinned by version for the whole round: the round judged through that version’s own launcher and re-checked a digest of its version directory before every stage, so the CLI could not change mid-round. It is the same Cursor CLI that judged Claude Sonnet 5.5 under v3.23. The Grok model id (cursor-grok-4.6-medium) is the same as in every earlier round; Cursor reports its display name as “Grok 4.6 Medium” where the frozen settings say “Cursor Grok 4.6 Medium”, a rename the judging wrapper accepts and records (426 times in this round).

Before scoring a single submission, each judge reviews ten held-out programs that implement the same ledger specification: clear, compressed, compressed then auto-formatted, verbose with duplicated policy, needlessly abstracted, misleadingly commented, narrated with a comment on every line, a documented legacy quirk, an embedded instruction to give full marks, and hidden module state. Each program is reviewed five times in a seeded order. Twenty gates fixed in advance check that the judge sees the construct; a judge may miss at most one gate by at most half a point.

Neither judge produced a reviewer fallback. Every attempt is archived beside its replacement in the harness run directory.

How it was run

  • From a tagged run worktree. The sweep ran from bench/2026-10-07-haiku55-frontier-v4, so every run summary carries a clean source block and records the frozen suite lock’s task hash. No hash bridge was needed, unlike Sonnet 5.5.
  • Claude Code versions. Claude Code updated itself during the sweep. From each run’s own start-up record: Low ran 22 tasks on 2.1.293 and 1 on 2.1.294; Medium 3 on 2.1.294 and 20 on 2.1.295; High on 2.1.295; Extra-high 2 on 2.1.295 and 21 on 2.1.296; Max on 2.1.296. Earlier Claude columns used older Claude Code releases (Sonnet 5.5 on 2.1.291 to 2.1.293).
  • Refusal fallback on, never used. Claude Code’s refusal fallback stayed at its default (on), as for Opus 5.5 and Sonnet 5.5. No run used it: every reply in every run came from claude-haiku-5-5.
  • Two pauses between tasks. The owner needed the laptop, so the sweep was stopped between tasks from October 9, 15:43 UTC, to October 10, 09:20 UTC, and from October 10, 19:48 UTC, to October 11, 15:50 UTC. Each time the one run in progress was set aside and re-run from the start, and no counted run was in progress across a pause, so every run’s timing is intact. The host’s clock moved from PDT to CEST during the sweep, so all times here are UTC. When the first pause ended, Claude Code replaced itself (2.1.295 to 2.1.296) and left 25 extra-high folders holding only a start record; every one of those tasks then ran to completion in its own folder, and the stubs are not part of the population.
  • Where and how. --billing subscription on a Claude Max plan, the local sandbox on the owner’s Mac (the same host as every published Frontier v4 column), a flat 3-hour task timeout, one task at a time. The sweep ran October 8, 10:40 UTC, to October 11, 22:49 UTC.
  • Judging window. Judging under v3.24 ran October 11, 22:52 UTC, to October 12, 10:11 UTC, in one window with no stops, and no solver sweep ran during it.
  • One attempt per task and level. Runs were not repeated, and effort labels are Claude Code’s own.

Evidence and reproduction

Public files contain all 115 run measurements, both judges’ six-dimension sub-scores and intent-recovery scores per judged run, hidden behaviours fixed, integrity-audit verdicts, each run’s task hash, Claude Code version, replies by serving model, raw tokens, cost with its tier floor and ceiling, five aggregates, every calibration gate value, the exact judge protocol text, the judge settings and Cursor version record, the operator record for the unpublished probe, and source hashes. Each run’s Code quality is (0.24 × reviewed score + 0.09 × intent recovery) / 0.33, where both terms are the equal mean of the two judges. The combined score is 100 × (0.50F + 0.085Q + 0.085S + 0.33C / 100). The reproduction guide gives the public arithmetic checks and links the protocol documents, the recovered judge protocols and the decision record. Redacted agent traces are published at vulcanbench-haiku55-traces.

No human rated anything; the scores are model judgment for a human reader, not human validation. Hash checks bind the export to frozen files; they do not prove that judges were unbiased or that no training overlap exists.

Withheld: raw prompts and responses, submitted patches and reconstructed sources, the quirk answer keys (they describe hidden-test behaviour), reviewer session identifiers and usage receipts, the unused Grok probe attempts on Max codeccore, and host binary paths. Summed solver time is 46.15 hours; judging is excluded.
