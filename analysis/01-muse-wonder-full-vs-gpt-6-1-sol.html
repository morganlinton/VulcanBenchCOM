Why Muse Wonder Full takes about 4x longer than GPT-6.1 Sol on the same tasks

2026-10-14 · Morgan Linton · VulcanBench Frontier v4, Low effort · trace analysis

On 23 hard legacy-reconstruction tasks, Muse Wonder Full averaged 27.2 minutes per task and GPT-6.1 Sol 6.3. Both solved almost all of them. The gap does not come from slower steps: each step takes about the same time. Muse Wonder Full takes about 3x as many steps and writes about 10x as much output to reach a similar result.

4.3xlonger per task (27.2 vs 6.3 min; medians 17.4 vs 4.1)
3.0xmore model calls per task (66 vs about 22)
10xmore output tokens per task (68.0k vs 6.8k)
18 vs 20tasks fully solved of 23; mean functional score 0.958 vs 0.972

Where the time goes

Muse Code logs every model call with its latency and every tool run with its start and end, so Muse Wonder Full's time can be split exactly. Codex does not log a timestamp per step, so the split for GPT-6.1 Sol is an estimate.

Muse Wonder Full spent 80% of its time in model calls. A call took 17.7 seconds on average, with a median of 5.8 seconds before the first token and about 98 tokens per second after it. Each call produced about 939 output tokens. The first call of every task carried about 25k input tokens of fixed instructions and context.

Ranked causes

  1. About 3x more round trips. This explains about half to two-thirds of the gap across all 23 tasks, and 65 to 90% once the two longest tasks are set aside. Muse Wonder Full often writes a script in one call and runs it in the next; about a fifth of its responses only write or edit a file. It tests one narrow hypothesis per run of the legacy binary (26 runs per task vs 7) and makes many small edits (19 vs 7). Across tasks, time tracks call count (correlation 0.91) and output tokens (0.99) closely.
  2. About 10x more output, mostly reasoning, even at Low effort. 38.3k reasoning tokens per task against 1.4k. At the measured streaming speed, generating that output accounts for about 14 minutes per task.
  3. A fixed wait before every response, multiplied by the call count. The median wait for the first token was 5.8 seconds, with a floor of about 3 to 4 seconds even for tiny calls. That is close to GPT-6.1 Sol's quickest steps, so it matters because there are so many calls, not because each one is slow.
  4. More tool time. 4.2 minutes per task against an estimated 1.2, mostly a few long randomized test runs.
  5. Harness overhead. About 1.2 minutes per task, including Muse Code's end-of-run goal and verify reminders, which run after the final answer.

Ruled out: retries (none), overlapping calls (none) and context size. Input grows from about 25k to over 120k tokens per call, about 97% cached, and call latency does not track it.

How the two models work

Muse Wonder Full: experimenter

  • Treats the legacy binary as a black box: form a hypothesis, run one probe, reason, refine.
  • Used disassembly on 7 of 23 tasks.
  • Edits late, in small patches, then loops through fuzzing, minimizing and fixing.
“Analyzing obfuscated binary behavior and mapping bullet clues to possible algorithm hypotheses for black-box testing.” (granarycore)

GPT-6.1 Sol: reverse engineer

  • Disassembles the binary early and reads large sections at once.
  • Used disassembly on 21 of 23 tasks.
  • Writes one large patch, runs one large randomized comparison against the binary, adds tests and stops.
“The updated implementation matched the binary across 90,000 randomized commands.” (blendcore, finished in about 3.5 minutes)

Both end with patches of similar size and similar correctness. On granarycore, Muse Wonder Full judged the binary obfuscated and ran about 30 black-box probes, while GPT-6.1 Sol decoded the binary's data tables directly. The longest task, lodgecore, took Muse Wonder Full 117 minutes and GPT-6.1 Sol 7.

Turning off Muse Code's skill reminder

Muse Code runs a skill-reminder plugin alongside the main model, and it can be turned off in Muse Code's settings. We repeated the Low run with it off. On the 19 tasks both runs completed, it saved little time and changed how the model worked.

  • The score change is within run-to-run noise for one run per task.

Method and caveats

Runs. Muse Wonder Full (muse-wonder-full-1.0, Contributor mode) in Muse Code 1.4.6 at Low effort on 13 and 14 October 2026: a first run with the skill reminder on (19 tasks completed before a usage limit) and a complete second run with it off (23 tasks). GPT-6.1 Sol in Codex 0.159.0 at Low effort on 30 September 2026. One run per task per model. Grading is the same for both; the functional score is the share of hidden behavior tests passed. Code quality was not judged for this analysis, so no combined score is shown and Muse Wonder Full is not on the leaderboard yet.

Measured. Muse Wonder Full's per-call latency, tokens, tool times and step counts come from Muse Code's session logs. GPT-6.1 Sol's step counts, tokens and step timestamps come from the Codex event stream and the harness trace.

Estimated. GPT-6.1 Sol's split between model and tool time, and its model-call count.

Not controlled. The harnesses differ: Muse Code has separate write, edit, todo and skill tools, reminders, and an outer sandbox in which the legacy binary must be copied before it runs, while Codex has one shell tool and patch edits. Some extra Muse steps come from the harness rather than the model. The runs were on different dates and hosts, and provider load is unknown. Muse logs do not record the effective reasoning effort, and Codex reasoning counts may not capture all hidden compute.
